# Requirements Document

## Project Description (Input)
**Who**: Obsidian の `_kanban/personal.md` のような「上部=完了タスク集／下部=未完了 todo」という構成のカンバン風マークダウンを手動運用している個人ユーザー（本人）。

**Current State**: 下部の未完了 todo を `[ ]` から `[x]` に書き換えるたびに、その行（および親子関係を持つ場合はインデント構造ごと）を毎回手動で上部の完了タスク集の末尾へカット&ペーストしている。順序ルール（親子関係を保つ）を踏み外すと履歴が壊れるため運用負荷とミスのリスクが高い。

**Desired Change**: Go 1.25+ で動作する CLI ツール `mdt`（Cobra サブコマンド構成）を構築し、`mdt sort <file>` で指定マークダウンファイルの未完了パート内の `[x]` 行を完了集末尾（=「最初の `[ ]` 行の直前」）へ自動移動する。親子インデント（タブ または半角スペース2個以上）を尊重し、(1) 子が完了でも親が未完了なら移動しない、(2) 親が完了でも子に未完了が残るなら移動しない、(3) 親子すべて完了なら段落をまとめて移動、というルールに従う。`--dry-run` で差分プレビュー、デフォルトは即上書き。引数なし起動時は Bubble Tea ベースの TUI スケルトンを起動する。AST には依存せず行ベース自前パーサで実装し、純粋関数（string → string）として TDD で構築する。git 等の外部副作用は持たない。

## Introduction
本仕様は、カンバン風の単一マークダウンファイル（上部=完了タスク集／下部=未完了 todo）に対し、`[x]` 化した todo 行を完了集末尾へ自動移動する CLI ツール `mdt sort` の機能要件を定義する。親子インデント構造を尊重し、書き込みは破壊的（即上書き）または `--dry-run` による差分プレビューの 2 系統を提供する。引数なし起動時の TUI スケルトンも初期スコープに含む。

## Boundary Context
- **In scope**:
  - 単一マークダウンファイル内の todo（`[ ]` / `[x]`）行に対する並べ替え（未完了パート→完了集末尾への移動）
  - 親子インデント（タブ または半角スペース 2 個以上）の構造判定と、ブロック単位の移動可否判定
  - `--dry-run` による非破壊実行（差分プレビュー）
  - 既定動作としての即上書き（バックアップ生成なし）
  - 引数なし起動時の TUI スケルトン（最低限の起動・終了動作）
- **Out of scope**:
  - 複数ファイルの一括処理、再帰的なディレクトリ走査
  - git 連携・自動コミットなどの外部副作用
  - 完了タスクの並び替え規則の選択（先入れ先出し以外）
  - front matter / 表 / コードブロック / リンク等のリッチ Markdown 要素に対する高度な保護
  - ファイルブラウザ等のリッチ TUI UX
  - 設定ファイル（`.mdtrc` 等）の読み込み・グローバル設定
- **Adjacent expectations**:
  - **Upstream（前提となる外部）**: Go 1.25+ ランタイム、Cobra 系 CLI フレームワーク（v1.10+）、Bubble Tea 系 TUI フレームワーク（v1 系）。これらの提供する機能（フラグ解析、サブコマンド階層、TUI イベントループ等）は本仕様が依存する前提とし、本仕様内では再実装しない。
  - **Downstream（将来の利用者）**: 同一バイナリ `mdt` 配下に追加されるサブコマンド（例: `mdt format`、`mdt stats` 等）。本仕様で確立されるパーサ／ロジック層は、これら将来サブコマンドからも再利用される想定であり、純粋関数化と決定性が前提となる。
  - **対象ファイル**: 利用者が手動運用する単一の Markdown ファイル。本仕様は当該ファイルに対する読み込みと上書きの責務のみを持ち、リポジトリ管理（git 等）やバックアップは利用者側の責務とする。

## Requirements

### Requirement 1: 未完了パート内の完了行を完了集末尾へ移動
**Objective:** カンバン風 Markdown を運用する個人ユーザーとして、未完了パートで `[x]` 化した todo を完了集末尾へ自動的に移動したい。手動カット&ペーストによるミスを排除するため。

#### Acceptance Criteria
1. When ユーザーが対象ファイルパスを指定して `sort` コマンドを実行した場合、the mdt CLI shall 当該ファイルを読み込み、未完了パート内の移動可能な `[x]` 行（およびその子孫ブロック）を完了集末尾へ移動した結果を生成する。
2. The mdt CLI shall 移動結果のファイル順序として、未完了パート内の出現順序を保ったまま、完了集末尾へ追記する形で並べる。
3. When 未完了パート内に移動可能な `[x]` ブロックが 1 つも存在しない場合、the mdt CLI shall 対象ファイルの内容を変更しない。
4. The mdt CLI shall 対象ファイル以外への書き込み・ネットワークアクセス・git などの外部副作用を発生させない。
5. If 指定ファイルが存在しない、もしくは読み取りに失敗した場合, the mdt CLI shall 失敗理由を含むエラーメッセージを表示し、非ゼロ終了コードで終了する。

### Requirement 2: 完了集と未完了パートの境界判定
**Objective:** 完了集と未完了パートの境界をユーザー入力に依らず機械的に決定し、移動先を一意に定めたい。

#### Acceptance Criteria
1. The mdt CLI shall ファイル先頭から走査し、最初に出現する `[ ]` 行の直前を「完了集の末尾／未完了パートの先頭」境界として扱う。
2. When ファイル内に `[ ]` 行が一切存在しない場合、the mdt CLI shall 未完了パートが存在しないとみなし、ファイル内容を変更せず正常終了する。
3. When ファイルの先頭行が `[ ]` で始まる場合、the mdt CLI shall 完了集が空であるとみなし、移動対象も存在しないため対象ファイルの内容を変更しない。
4. The mdt CLI shall 完了集側に存在するチェックボックス以外の行（見出し、空行、プレーンテキスト等）を改変せずそのまま保持する。
5. The mdt CLI shall 未完了パート内に存在するチェックボックス以外の行（見出し、空行、プレーンテキスト等）について、移動の対象とせずその位置のまま保持する。

### Requirement 3: 親子インデント構造の尊重と移動可否判定
**Objective:** 親子関係を持つ todo の履歴を壊さず、論理的に整合した状態でのみ移動させたい。

#### Acceptance Criteria
1. The mdt CLI shall 行頭インデントとして、タブ文字 1 個分または半角スペース 2 個以上の差を、親子関係（深さの増加）として判定する。
2. The mdt CLI shall ある行を「親」と認識した場合、当該行より深いインデントが連続して続く範囲を当該行の子孫ブロックとして扱う。
3. If ある親 `[x]` 行の子孫ブロック内に `[ ]` が 1 つでも残っている場合、the mdt CLI shall 当該親ブロックを移動しない。
4. If ある子 `[x]` 行の祖先のいずれかが `[ ]` のままである場合、the mdt CLI shall 当該子ブロックを単独でも親と切り離して移動しない。
5. When ある親 `[x]` 行と、その子孫ブロック内のすべての todo 行が `[x]` である場合、the mdt CLI shall 当該親ブロックを子孫を含めひとまとまりとして完了集末尾へ移動する。
6. The mdt CLI shall 移動対象ブロックの内部行順序、インデント文字（タブ／スペース）、およびインデント幅を変更せず保持する。

### Requirement 4: Dry-run と書き込みモード
**Objective:** 破壊的な書き換えに先立って差分を確認できる手段を提供し、誤適用を回避したい。

#### Acceptance Criteria
1. When ユーザーが `--dry-run` フラグを付けて `sort` コマンドを実行した場合、the mdt CLI shall 対象ファイルへの書き込みを行わず、移動結果の差分プレビューを標準出力に表示する。
2. The mdt CLI shall `--dry-run` の差分プレビューにおいて、移動された行・移動先・変更されなかった範囲が一目で識別可能な形式（例: 行単位の追加／削除表示）で出力する。
3. When ユーザーが `--dry-run` を指定せずに `sort` コマンドを実行した場合, the mdt CLI shall 対象ファイルを移動結果で上書きする（バックアップは生成しない）。
4. The mdt CLI shall 上書き時に元ファイルの改行コード（LF / CRLF）および末尾改行の有無を保持する。
5. If 書き込み処理が途中で失敗した場合, the mdt CLI shall 元ファイルが破損した中間状態で残らないようにし、エラーメッセージを表示し、非ゼロ終了コードで終了する。
6. The mdt CLI shall `--dry-run` 実行時にファイルの内容変更を一切行わない。

### Requirement 5: CLI コマンド構成と終了コード規約
**Objective:** 将来 `mdt` 配下にサブコマンドが追加される前提で、安定した CLI インターフェースと終了コード規約を提供したい。

#### Acceptance Criteria
1. The mdt CLI shall `sort` をサブコマンドとして提供し、対象ファイルパスを位置引数として受け取る。
2. When ユーザーが `--help` または `-h` フラグを指定して `mdt` または `mdt sort` を実行した場合、the mdt CLI shall 利用方法、利用可能なサブコマンド／フラグの説明を表示し、終了コード 0 で終了する。
3. The mdt CLI shall 正常完了時に終了コード 0、引数や使用方法の不正時に非ゼロ終了コード、実行時エラー（読み書き失敗等）時に非ゼロ終了コードを返す。
4. When ユーザーが `sort` サブコマンドに対し必須の対象ファイルパスを省略した場合, the mdt CLI shall 使用方法のヒントを含むエラーメッセージを表示し、非ゼロ終了コードで終了する。

### Requirement 6: 引数なし起動時の TUI スケルトン
**Objective:** 将来の TUI 拡張に備えた起動経路を確保し、利用者が GUI 的入口を期待しても破綻しないようにしたい。

#### Acceptance Criteria
1. When ユーザーがサブコマンドや引数を一切指定せずに `mdt` を実行した場合、the mdt CLI shall TUI スケルトン画面を起動する。
2. The TUI スケルトン shall 利用者がキー入力（少なくとも `q` キーおよび `Ctrl+C`）によって明示的に終了できる手段を提供する。
3. The TUI スケルトン shall 初期スコープでは、ファイル選択ブラウザ・編集操作・複数画面遷移などのリッチ UX を提供せず、起動・初期画面表示・終了のみを実装する。
4. When ユーザーが TUI スケルトンを終了操作で抜けた場合, the mdt CLI shall 終了コード 0 で終了する。

### Requirement 7: ロジックの純粋性と決定性
**Objective:** ソートロジックを TDD で構築・保守し、将来の `mdt` サブコマンドからも再利用可能にしたい。

#### Acceptance Criteria
1. The mdt CLI shall ソートロジックを「入力 Markdown 文字列 → 出力 Markdown 文字列」の純粋関数として呼び出し可能な単位で提供する。
2. The mdt CLI shall 同一の入力に対して常に同一の出力を返す（決定的に動作する）。
3. The mdt CLI shall ソートロジック内部から、対象ファイル以外への入出力（標準入出力以外のファイル書き込み、ネットワークアクセス、外部プロセス起動、git 操作等）を発生させない。
4. The mdt CLI shall 外部 I/O（ファイル読み書き、TUI 描画、CLI フラグ解析）と純粋ロジックを分離し、ロジック単体でテスト可能な構成を保つ。
