# Brief: kanban-sort

## Problem
Obsidian の `_kanban/personal.md` のような「上部=完了タスク集／下部=未完了 todo」という構成のマークダウンを運用しているが、下部で `[ ]` を `[x]` に書き換えた todo を、毎回手動で上部の完了タスク集の末尾へカット&ペーストするのが面倒。順序ルール（親子関係を保つ）を踏み外すと履歴が壊れる。

## Current State
- 参考ファイル: `/Users/kazuki/ghq/github/kazuki-oshino/kazuki_obsidian_vault/_kanban/personal.md`
- 構造: ファイル先頭から続く完了タスク群 → 空行・空白を挟んで未完了 todo 群（最初に `[ ]` 行が現れた時点で「未完了パート」とみなす）
- 現状は手動で上に移しているため、運用負荷が高くミスも起きやすい

## Desired Outcome
- 指定したマークダウンファイル内の未完了パートで `[x]` になった行を、完了集の末尾（=「最初の `[ ]` 行の直前」）に移す
- インデント付き（親子）todo は次のルールで判定:
  - 子が完了でも親が未完了 → 移動しない
  - 親が完了でも子に未完了が残る → 移動しない
  - 親子すべて完了 → 段落（インデント構造）を保ったまままとめて移動
- 移動順序: 未完了パート内で上から順に走査し、移動可能なものを完了集末尾に追加していく
- git 等の外部副作用は無し（純粋なファイル書き換えのみ）

## Approach
**Approach A: 行ベース自前パーサ + Cobra サブコマンド + Bubble Tea TUI**

- 各行を「インデント深さ + チェックボックス状態 + 残りテキスト」に分解する軽量パーサで処理
- Cobra でサブコマンド構成にし、初期機能は `mdt sort <file>`（または将来サブコマンド名を変える可能性あり）。`--dry-run` で書き込み無し・差分のみ表示
- 引数なしで起動した場合は Bubble Tea ベースの TUI を起動し、ファイル選択や操作を行う想定（初期リリースでは最低限のスタブで可）
- 完了集と未完了パートの境界判定: ファイル先頭から最初に現れる `[ ]` 行の直前
- 親子判定: タブまたは半角スペース2個以上のインデント差で親子と見なす

**Why this approach**
- 要件は行単位の todo 操作なので、AST までは不要（goldmark は過剰）
- Cobra と Bubble Tea は `RunE` 内で `tea.NewProgram(...).Run()` を呼ぶ定番パターンで共生する。将来「markdown 関連機能を増やす」前提に対し、サブコマンド構成が一番素直
- 純粋関数（in-memory の string → string 変換）として実装すればテストがシンプルになり、TDD と相性が良い

## Scope
- **In**:
  - 単一マークダウンファイルを対象に、未完了パートの `[x]` を完了集末尾へ移動
  - 親子インデント（タブ／スペース2個以上）の構造判定とルールに沿った移動
  - `--dry-run` フラグでの非破壊実行（差分プレビュー）
  - デフォルトは即適用（バックアップ無しで上書き）
  - 引数なし起動時の Bubble Tea TUI スケルトン（最低限の画面）
- **Out**:
  - 複数ファイル一括処理
  - git 連携・自動コミット
  - 完了タスクのソート規則（先入れ先出し以外）の選択
  - Markdown のリッチ要素（表、コードブロック、front matter）の高度な保護
  - ファイル選択ブラウザ等の TUI リッチ UX（初期スコープではスタブのみ）

## Boundary Candidates
- **パーサ層**: 行→構造化トークン（インデント深さ、チェック状態、テキスト）への変換
- **ドメインロジック層**: 完了集／未完了パートの境界判定、親子ツリー構築、移動可否判定、再構築
- **ファイル I/O 層**: 読み書き、`--dry-run`、書き込み前後のバリデーション
- **CLI 層 (Cobra)**: サブコマンド定義、フラグ解析、終了コード規約
- **TUI 層 (Bubble Tea)**: 引数なし起動時のエントリポイント、Cobra ハンドラから呼び出される画面モデル

## Out of Boundary
- 設定ファイル（`.mdtrc` 等）の読み込み・グローバル設定
- マークダウンの整形・lint（フォーマッタ機能）
- todo 以外の Markdown 要素の自動編集
- Obsidian 固有のリンク／エイリアス／プラグイン挙動の理解

## Upstream / Downstream
- **Upstream**:
  - Go 1.25+ ランタイム
  - `github.com/charmbracelet/bubbletea` (v1 系)
  - `github.com/spf13/cobra` (v1.10+)
- **Downstream**:
  - 将来追加される他の `mdt` サブコマンド（例: `mdt format`, `mdt stats`, `mdt link-check` 等）
  - パーサ／ドメインロジック層は他サブコマンドからも再利用される想定

## Existing Spec Touchpoints
- **Extends**: なし（このリポジトリ初の spec）
- **Adjacent**: なし

## Constraints
- Go 1.25+ で動作すること
- `just` をタスクランナとして利用（プロジェクトルールに準拠）
- TDD で開発する（探索→Red→Green→Refactor）
- 静的検査可能なルールは linter / ast-grep に寄せる
- ライセンスは MIT（Bubble Tea）と Apache-2.0（Cobra）を同梱可能な構成にする
- 破壊的書き込みになるため、`--dry-run` の出力フォーマットは差分が一目で分かること
